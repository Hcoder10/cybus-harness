# cybus-harness

A multi-agent harness that builds Roblox games from a pitch, with **taste you can verify**: every screen,
moment and system is planned against a written style guide, built, **captured from a running Studio**, judged
by a vision model against genre-general rubrics, and repaired by a separate fixer until it passes.

It runs any OpenAI-compatible or Anthropic model. It is built for **Cybus** (Qwen3.8-27B, a vision-language
model, plus our adapters), and it is designed around what a 27B model can do reliably. Two design points follow
from that:

- **The workflow holds the long horizon.** Every agent call is a short, fully briefed task: one work item or
  one fix list, with the files it owns, the style tokens, the rubric it will be judged on, the kit API, and the
  specs for its tools.
- **Nothing needs uploads, keys or image generation.** Art is painted from declarative texture specs and
  decoded into EditableImages at runtime. Animation is keyframe data played on Motor6D rigs. Audio comes from
  public Creator Store search.

## What a build does

```
plan       lead writes the game plan; a critic reviews it; one revision
style      art director writes the style guide -> Tokens.luau + lighting generated by code
architect  files, remotes, debug commands, 8-16 owned work items
scaffold   runtime kit + tokens + loadable stubs, synced and boot-checked in Studio
build      per item, as dependencies finish: build -> gates -> capture in Studio -> vision judge -> fixer (x repair
           rounds). The gates need no Studio: syntax, requires that cannot reach their module, and Roblox API
           misuse (properties, enum items, classes that do not exist); failures go straight back to a fixer.
integrate  one play session captures everything; runtime errors and panel critiques are routed to owners
polish     five critics with different lenses; fixes loop until no blocker/major (or budget)
report     per-item scores, captures, the saved place; optional benchmark evidence pass
```

## Requirements

- Python 3.11 with the packages the harness imports: `httpx`, `jsonschema`, `pillow`, `numpy`, `pyyaml`, `mcp`,
  `fastapi`, `uvicorn`, `openai`, `anthropic`.
- Roblox Studio with the Studio Bridge plugin and server (`http://localhost:3000/mcp`).
- `luau-analyze` (the syntax gate), `ffmpeg` (frame strips), and optionally `rojo` (the place template).
- `luau-lsp` 1.70+ with Roblox's `globalTypes.None.d.luau` (the API gate), in `~/bin` or set with
  `HARNESS_LUAU_LSP` / `HARNESS_ROBLOX_DEFS`. Without them the API gate is skipped and those errors only show in
  Studio. Live, it found 9 to 71 per game.
- A model endpoint. See [serve/README.md](serve/README.md) to serve Cybus with vLLM.

Check everything with `python -m harness.doctor`.

## Run

```bash
export HARNESS_DEFAULT_BASE_URL=http://<host>:8000/v1 HARNESS_DEFAULT_MODEL=cybus HARNESS_DEFAULT_API_KEY=...
python -m harness.doctor                                   # tools, disk, bridge, one Studio window, models see images
python -m harness.workflows.build_game --idea bench/ideas.yaml#lakeside_fishing --run-dir runs/fishing
python -m bench.run_bench --only lakeside_fishing --hours 6   # build + evidence + independent scoring
```

Roles are set with `HARNESS_<ROLE>_BASE_URL/_MODEL/_API_KEY/_PROVIDER`; the roles are lead, art, builder,
critic and judge, and each falls back to `HARNESS_DEFAULT_*`.

A run directory holds:
- `plan.json`, `style.md`, `architecture.json`
- `workspace/src` (the game's source, Rojo layout)
- `verdicts/`, `panel_r*.json` and `work/captures/`
- `journal.jsonl`: resumable, since completed agent calls replay from it
- `report.json` and `place/final.rbxl`

**Studio safety:**
- The harness opens its own fresh local place and refuses to start while any other Studio window is open,
  because the bridge token is shared between windows.
- Every write is checked inside Studio against a run marker.
- Protected places are always refused.

## Codex and Claude Code

Cybus also works inside other agent harnesses:
- **Claude Code:** through `serve/anthropic_gateway.py`. See [serve/claude_code.md](serve/claude_code.md).
- **Codex:** as a custom provider. See [serve/codex.md](serve/codex.md).
- **Either:** the taste and craft tools are available over MCP (`python -m mcp_server.server`): capture, judge,
  pairwise, rubrics, style guide, `check_game` (the same syntax, wiring and API gates), and more.

In those harnesses the model has to carry the long horizon itself, so expect this harness to do much better.

## Layout

```
harness/     llm, agent, workflow engine, judge, stage (Studio sessions), prompts, schemas, tokens, doctor
harness/kit/       the runtime kit every game ships with (Luau): Maid, Spring, Motion, Shake, Sound, Screen, Debug,
                   Textures/TexCodec, Anim/AnimCore, ...
harness/tools/     studio bridge client, capture, workspace sync, luau checks, texture specs + packs, clips,
                   audio search
harness/playbooks/ rubrics (12 aspects), style-guide template, craft notes, spec references
harness/workflows/ build_game
serve/       vLLM launch, Anthropic gateway, Codex config
mcp_server/  harness tools over MCP
bench/       new-genre ideas, evidence conventions, runner, scorer
```
